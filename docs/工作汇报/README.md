# 工作汇报

存放周报、月报和阶段汇报。与 `docs/工作记录/` 的分工：

- **工作记录**：按天记，重过程、踩坑、命令和数据，写给下一次接手的自己。
- **工作汇报**：按周/月/阶段汇总，重结论、指标、风险和计划，写给导师、团队或合作方。

## 命名约定

- 周报：`YYYY-Www_周报.md`，例如 `2026-W46_周报.md`
- 月报：`YYYY-MM_月报.md`
- 阶段汇报：`YYYY-MM-DD_阶段汇报_主题.md`

## 写作约定

1. **结论先行**：开头一段说清本周做到什么、没做到什么。
2. **数字带条件**：速度、误差、时长都注明测试条件和样本量；没有数据的写“未测”。
3. **区分事实与判断**：已验证的写“实测”，推测明确标“推测”，不要把推测写成结论。
4. **问题带下一步**：每个遗留问题写清影响、证据、负责人/计划。
5. **可追溯**：引用 `docs/工作记录/` 的当日记录、原始日志和 CSV 路径。

## 建议结构

1. 本周摘要（3—5 条）
2. 工作进展（按技术主线，不按流水账）
3. 关键结果与数据
4. 问题与风险
5. 下周计划（按优先级，带验收标准）
6. 产出物清单
7. 附：每日工作流水
