# 2026-11-18 干扰 / 断联测试小结

> 针对 2026-11-12 记录的「电机负载下 USB ACM 卡死、`$KSXT` 停更」问题
> 平台：Orange Pi 5 Pro（`orangepi5pro`），UM982 + Air700E，串口 `/dev/ttyACM3`
> 记录人：现场 + 助手

## 0. 一句话结论

**在今天的条件下没有复现串口冻结 / USB 断联。** 连续监测（含原地旋转与 5 分钟静置）里，串口始终 28 行/秒、最大间隔 0.15 s，坏帧 0、USB 复位 0、重连 0。
另外，连日来「网页能动但车不动」的真正原因是**驱动器端接线插错位置**，与电磁干扰无关，已在今天解决。

## 1. 目标

验证 11-12 的假设：电机大电流 / 换向产生的干扰会击穿 USB 链路，导致 `$KSXT` 停更（当天出现过 129 秒冻结）。

## 2. 测试条件

| 项 | 内容 |
|---|---|
| 板子位置 | 夹在电机与控制器之间（最严苛的耦合位置） |
| 驱动方式 | 原遥控器 + 接收机原地旋转；Pi 不参与驱动 |
| 无线 | 热点先远后近：-78 ~ -54 dBm → 移到板子旁后 -35 ~ -40 dBm |
| 环境 | 地下车库，无卫星视野（GGA 质量 0，星数 0） |
| 期间操作 | 同时用网页遥控界面推杆 |

## 3. 方法

两个脚本，**同一时刻只允许一个进程读串口**（否则数据被分走）：

- `emi_monitor.py`：串口行率、最大间隔、NMEA 校验、USB 内核事件、WiFi 信号、ping
- `field_monitor.py`：合并上述指标 + GGA/GSV 解算指标，输出 CSV + 事件日志

判据：

| 指标 | 正常 | 异常 |
|---|---|---|
| 串口行率 | ~28 行/秒 | 掉到 0 |
| 相邻数据间隔 | ≤0.2 s | >0.5 s |
| NMEA 校验 | 0 错 | 出现坏帧 |
| USB 事件 | 0 | `usb 5-1: reset`、`cdc_acm` 断连 |
| WiFi / ping | ≥-55 dBm，丢包 0 | 信号跳水、持续丢包 |

### 4.3 测量本身的三次假象（重要，避免误判）

| 时间 | 现象 | 根因 | 处理 |
|---|---|---|---|
| 15:40:47 | 报 1.04 s 断流 | 脚本在串口循环里同步跑 `ping`，超时阻塞 1 s | ping/WiFi 移到独立线程，复测消失 |

### 4.4 网页遥控链路

- 服务端**没有**出现 `Command timeout`（断流停车）记录。
- 有 13 次客户端连接重置（请求超过 400 ms 被前端 abort），TCP 重传 313/47929 ≈ **0.65%**。
- 指令到端验证：油门 1.0 → CH1 脉宽 1.0 ms；转向 ±4.0 → CH2 1.0/2.0 ms，回中正常。

## 5. 结论

1. **未发现电磁干扰击穿 USB / 串口链路的证据**：原地旋转 10 分钟 + 静置 5 分钟，零断流、零坏帧、零 USB 复位。
2. **11-12 的串口冻结未复现**；原地旋转不足以触发，或触发条件与当天不同（负载、转速、线束、供电）。
3. **「车不动」与干扰无关**：驱动器端接线插错位置，已解决。
4. 本次测试用的监测工具存在 3 处会制造假象的问题，均已修复（见 4.3），后续数据可信度提高。

## 6. 局限

- **工况不同**：原地打滑的电流、振动、履带负载都小于实际行驶与高速转向（11-12 冻结发生在指令 3.0–4.0 的高速转向）。
- **耦合路径不同**：Pi 未参与驱动（PWM 线不接驱动器），线束布局与实车不一致。
- **无卫星**：室内 0 星，解算层（质量/差分龄期/SNR）本次未观测。
- **未直接测供电**：没有测量 5V 轨的电压跌落；USB 无事件只能排除「被拉挂」，排不掉「缓慢掉压」。

## 7. 下一步

1. 室外有固定解后，用 `field_monitor.py 3600` 跑真实工况（直线 + 转向 + 负载），按「基线 / 转动」区间对比。
2. 测试时记录 MARK 时间点（开始转、停止），便于事后对齐。
3. 若要直接排除供电：5V 串 USB 电压记录仪或 INA219；4G 侧轮询 `AT+CSQ`。
4. 需要更深一层时，给 UM982 开 `CHANSTATUS`（每颗星 SNR/锁定时间/周跳）。
