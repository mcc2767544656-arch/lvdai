## 2. 遥控链路：延时与「松手不停车」

### 现象
轻触 0.5s，电机持续约 2s 才停；整体控制发飘。

### 定位过程
1. 在 `web_teleop` 的 `/api/control` 加临时日志，记录每条指令到达时间
2. 同时 20ms 采样 PWM sysfs，对照指令时间戳
3. 结论：
   - **指令一旦到达，PWM 回中位只要 8–32ms**（软件链路没问题）
   - 但日志里有 **10 次 `Command timeout, stopping`** → 说明松手的那条 `{0,0}` 根本没送达
   - 超时兜底 = `web_teleop` 1.0s + `pwm_driver` 0.5s ≈ **1.5–2s**，与现象吻合
4. 指令流间隔实测有 400–900ms 空档 → 200ms 心跳没在发（一个卡死的 fetch 会让 `controlInFlight` 永久为真）

### 修复（前端 `static/index.html` + 服务端 `run.py`）
| 改动 | 作用 |
|---|---|
| `fetch` 加 400ms `AbortController` 超时 | 单个请求卡死不再堵死通道 |
| 同一时刻只允许一个请求在途，结束时补发最新值 | 防止请求堆积 |
| 心跳 200ms → **50ms 固定重发**（非零时） | 按住不动时指令不再停在旧值 |
| 松手/急停/重置 → **连发 3 次零指令**（间隔 60ms）+ `sendBeacon` | 单次丢失不再导致「继续跑」 |
| 状态轮询 200ms → 300ms，且上一帧没回就不发 | 减少连接占用 |
| 服务端开 **HTTP/1.1 keep-alive** + 所有响应补 `Content-Length` | 手机端不必每请求重建 TCP 连接 |
| 页面加 `Cache-Control: no-store` | 避免手机缓存旧 JS |
| `command_timeout` 1.0s → **0.3s**，`output_rate` 10Hz → **20Hz** | 万一丢包，最多多走 0.3s |

### 验证
- 第二个 HTTP 请求复用连接（`num_connects=0`）
- `node.js --check` 通过页面脚本
- 用户反馈「问题基本缓解」

### 修复过程中引入并修掉的回归
开 keep-alive 后 `web_teleop` 停机被空闲连接拖住，日志出现
`Node 'web_teleop' did not terminate in 5.0s, sending SIGKILL`。
修法：`daemon_threads = True`、`block_on_close = False`、空闲连接 5s 超时、退出时 `server_close()`。现在同一秒优雅退出。

## 3. 混控与方向

### 结论
- 驱动器原本接普通 RC 遥控器，**混控在驱动器内部**。
- 软件做差速（`differential`）+ 驱动器再混 → 双重混控，表现为「前进只动一边履带」。
- 因此改为 `drive_mode: direct`：**CH1 = 线速度（油门），CH2 = 角速度（转向）**，软件只管映射和限幅。

### 配置（`configs/graphs/web_pwm_teleop.yaml`）
```yaml
      drive_mode: direct
      invert_linear: true      # 直驱模式下前进/后退实测与摇杆相反
      invert_angular: true     # 左右转向同样相反
```

### 关键坑：只重启 dataflow 不会重载 YAML
图在 `runtime start` 时解析并缓存。改了 YAML 后只 `start-dataflow`/`stop-dataflow` **不生效**，必须重启整个 runtime（或使用下面第 4 节的热加载）。

## 4. 运行图热加载（新增能力）

### 原有机制
控制缓冲区命令里的 `start_dataflow` 支持 `preset_yaml` 字段，runtime 会调 `_switch_task_preset()` 换配置并重建节点图（进程不重启）。但：
- CLI 的 `runtime start-dataflow` **没有**这个参数
- 白名单只允许 `examples/` 下的纯文件名

### 本次改动
| 文件 | 改动 |
|---|---|
| `tools/cli/core/cli.py` | `start-dataflow` / `restart-dataflow` 增加 `--preset NAME` |
| `tools/cli/commands/runtime_cmd.py` | `start_dataflow(preset)` / `restart_dataflow(preset)`，把 `preset_yaml` 写入控制命令 |
| `edge/runtime/main.py` | `_switch_task_preset()` 白名单扩为 `configs/graphs/` + `examples/`，错误信息列出搜索路径 |

### 用法
```bash
python3 -m tools.cli.core.cli runtime stop-dataflow
python3 -m tools.cli.core.cli runtime start-dataflow --preset tillage_operation
# 或一步
python3 -m tools.cli.core.cli runtime restart-dataflow --preset web_pwm_teleop
```

### 实测
- `config_path` 从 `configs/graphs/...` → `examples/_reload_probe.yaml` → 再切回，**runtime PID 全程不变**
- 错误预置不会搞挂框架：日志 `Unknown task preset: does_not_exist (searched configs/graphs and examples)`，runtime 存活、数据流保持停止
- 注意：CLI 是「发完就返回」，实际结果看 `runtime status` 的 `command_status` 或 `/tmp/nodeflow_runtime.log`
- 注意：`tools/cli/cli/commands/runtime_cmd.py` 是一份**未被引用的旧副本**，未改动

## 6. 速度 / 角速度标定

### 方法
- 指令侧：直接读 `web_teleop.velocity_cmd` 共享缓冲区（20Hz）
- 输出侧：读 `pwm_driver.pwm_status`（左右通道 duty）
- 实际侧：UM982 `$KSXT` 10Hz（经纬度、双天线航向、地面速度、东北向速度）
- 脚本：`tools/采集脚本_teleop_rtk_log.py`、`tools/扫档脚本_teleop_sweep.py`

### 结果：油门（CH1）
| 脉宽 | 偏移 | 实测速度 |
|---|---|---|
| 1.500 ms | 0 | 0 |
| 1.463 ms | 0.037 | 0.01（未动） |
| 1.369 ms | 0.131 | 0.43 m/s |
| 1.297 ms | 0.203 | 0.67 m/s |
| 1.166 ms | 0.334 | 0.99 m/s |
| 1.134 ms | 0.366 | 1.20 m/s |
| 1.036 ms | 0.464 | 1.52 m/s |
| **1.000 ms** | **0.500** | **1.61 m/s** |

拟合（按样本加权）：`v ≈ 2.94 × 偏移ms + 0.09`
→ **指令 1.0 m/s 实际约 1.56 m/s（增益 1.56×）**；死区几乎为 0。

### 结果：转向（CH2）
| 指令 rad/s | 实测 | 折合 |
|---|---|---|
| 0.5 | 4–5 °/s | 0.07–0.09 |
| 1.0 | 27.6 °/s | 0.48 |
| 1.5 | 49 °/s | 0.86 |
| 2.0 | 66–68 °/s | 1.15–1.19 |
| 2.5 | 84–90 °/s | 1.47–1.57 |
| 3.0 | 96–98 °/s | 1.67–1.71 |
| **4.0** | **124–126 °/s** | **2.16–2.20** |

拟合（|cmd| ≥ 1）：`ω ≈ 0.561 × cmd` rad/s
→ **满杆 4.0 实际约 2.2 rad/s（增益 0.56×）**；0.5 以下明显偏离直线，近零有死区。

### 直线偏移（左右履带差异）
纯直线段（角速度指令 = 0）的航向漂移：

| 指令 | 速度 | 漂移 |
|---|---|---|
| +1.0 | 1.6 m/s | **+1.1 °/s** |
| −1.0 | 1.6 m/s | **−1.1 °/s** |
| +0.5 | 0.94 m/s | +0.67 °/s |

- 符号随方向翻转 → 是**两侧履带速度差**（约 `Δv ≈ 0.01 m/s`，0.6%），不是地面起伏
- 后果：跑 10 m 航向偏约 7°，横向偏约 **0.6 m**
- 天线的安装偏角只会造成**恒定航向误差**，不会造成漂移，因此这一项与天线无关

### 电压影响
当日 79.3V ≈ 满电的 90.5%。直流电机转速基本正比电压，故表中速度大致比满电低 10%。**换电池或充电后需重新抽检。**
