# 室内无数据 Soak 测试报告（2026-11-03）

## 环境

- 场地：室内，无卫星视野，GGA 质量 0、可见星 0；
- 4G：未拿到 IP，NTRIP 停在 `wait IP_READY`；
- 设备：UM982 + Air700E，数据口 `ttyACM3`（by-id if06）；
- 配置：KSXT/GPTHS 10Hz，GGA/RMC 1Hz（已 `SAVECONFIG`）。

## 测试内容

连续 180 秒读取数据口，统计语句频率、最大间隔、解析结果、驱动质量门控。

## 结果

| 语句 | 条数 | 实测频率 | 最大间隔 |
|---|---|---|---|
| `$KSXT` | 1850 | 10.27 Hz | 136 ms |
| `$GPTHS` | 1850 | 10.27 Hz | 136 ms |

| `$GNRMC` | 185 | 1.03 Hz | 1001 ms |

- 端口无丢失、模块无重启；
- 解析成功 3884 条，**驱动接受 0 条**（正确：质量 0 全部被 `min_rtk_quality=3` 拒绝）；
- NTRIP 配置回读不变：`103.40.12.16,8002,RTCM33_GRCEJ,cqcc139580,...`。

## 发现的问题：HDT 假航向

统计里出现 **185 次 `heading_valid=True`**，正好 1Hz。定位到 `$GPHDT,0.0000,T`：

- HDT 语句本身**没有解状态字段**；
- 失锁时它仍然输出 `0.0000,T`；
- 解析器把它当成有效航向，导致每秒注入一次 0°。

当前因为质量门控（GGA/KSXT 质量 0）没有真正输出，但一旦定位有效、航向解暂时失效，就可能输出错误的 0° 航向。

## 修复

- `NMEAParser` 新增 `allow_hdt` 参数（默认 `True`，保持兼容）；
- `run.py` 在双天线模式下固定 `allow_hdt=False`，只认 `KSXT`/`GPTHS`；
- 新增测试：关闭 HDT 后 `$GPHDT` 返回 `None`，驱动解析器 `allow_hdt is False`。

修复后复测 20 秒：

```
解析 376 条；heading_valid 0；驱动接受 0
KSXT 188 / GPTHS 188 / GGA 19 / HDT 19
```

假航向消失。

## 结论

- 室内无数据状态下，链路、频率、看门狗、质量门控均正常；
- 驱动不会因为无定位而输出伪造数据；
- 固定解、精度、航向准确性仍需到室外接天线后按 `RTK 无车测试方案` 继续验证。
