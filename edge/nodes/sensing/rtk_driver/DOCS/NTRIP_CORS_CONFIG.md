# OEM700 / Air700E NTRIP（CORS）配置说明

来源：`OEM700_2217_V3.doc`（供应商提供的模块命令手册，5 页）+ 现场实测。

## 1. 命令格式

```
$snp,<host>,<port>,<mount point>,<user name>,<password>,<up gga>,*XX
```

手册示例：

```
$snp,ntrip.gnss-info.com,2101,SEP01,ntrip,ntrip4u,1,*4E
```

字段说明：

| 字段 | 含义 | 本系统取值 |
|---|---|---|
| host | CORS 域名或 IP | 旧：`rtkcq.cn` / `103.40.12.16`；新：`120.253.239.161` |
| port | 端口 | **旧供应商**：`8001`（ITRF2008）/ `8002`（WGS84）/ `8003`（CGCS2000）；**新供应商**：`8001`（CGCS2000）/ `8002`（WGS84） |
| mount point | 挂载点 | `RTCM33_GRC`（三星八频）或 `RTCM33_GRCEJ`（五星十六频） |
| user name | 账号 | 旧：`cqcc139580`；新：`cvha2771` |
| password | 密码 | 已单独提供，**不写入本仓库** |
| up gga | 是否上传 GGA | `1` |

## 2. 校验和

算法：`$` 之后、`*` 之前所有字符的 **逐字节 XOR**，两位大写十六进制。

已验证：

| 命令体 | XOR | 完整命令 |
|---|---|---|
| `sne,1,` | `49` | `$sne,1,*49` |
| `sne,0,` | `48` | `$sne,0,*48` |
| `gnp,` | `55` | `$gnp,*55` |
| `snp,ntrip.gnss-info.com,2101,SEP01,ntrip,ntrip4u,1,` | `4E` | 手册示例 |

注意：末尾逗号也算进校验和。

## 3. 开关与查询

| 命令 | 作用 |
|---|---|
| `$sne,1,*49` | 打开 NTRIP |
| `$sne,0,*48` | 关闭 NTRIP |
| `$gnp,*55` | 查询 NTRIP 参数（手册只给了这一条，按命名推断为 get） |
| `$snp,...` | 设置 NTRIP 参数 |

## 4. 现场实测（2026-11-03，已确认）

**模块的 `$` 命令口就是 NMEA 数据口**，不是 AT 口，也不是 Lua REPL。

| 端口 | 行为 |
|---|---|
| 数据口（最初 `ttyACM3`，重枚举后 `ttyACM4`） | `$gnp` / `$snp` / `$sne` 都在这里响应，同时输出 NMEA |
| `ttyACM0` | 静默，不发 `$gnp` 响应 |
| `ttyACM1` | LuatOS Lua REPL，发 `$` 会报 `unexpected symbol near '$'` |
| `ttyACM2` | 高速二进制日志，不要 `cat` |

实测过程：

1. 查询旧配置：

```
$gnp,103.143.19.54,8002,RTCM33GRCEJ15,gj011,14231,1,*10
```

2. 写入新配置后模块回 `$snp,ok,*69`，再查：

```
$gnp,103.40.12.16,8002,RTCM33_GRCEJ,cqcc139580,31818,1,*5B
```

3. 写入后模块**重启并重新枚举 USB**：`ttyACM3` 消失，变成 `ttyACM4`。重启后配置仍在（已写 NVM）。

> 因此脚本不要写死端口号。按 `/dev/serial/by-id/usb-AirM2M_AirM2M_Compo_000000000001-if06` 找，或写配置后重新扫描 `/dev/ttyACM*`。

## 6. 尚未打通的部分

- **4G 没有 IP**：`ip addr` 只有 `wlan0` 和 `docker0`，没有 wwan/ppp 接口；日志停在 `I/user.ntrip wait IP_READY`。
- **GNSS 没有定位**：GGA 质量 `0`、可见卫星 `0`（天线未接或室内无视野）。
- 所以暂时无法验证 `I/user.ntrip recv:` 和 RTK 固定解，账号写入本身已确认成功。

## 7. 验证方法（等 4G 和天线就绪）

1. 接好 GNSS 天线，放到室外/窗边。
2. 确认 4G 拿到 IP（出现 wwan/ppp/usb 网卡，或日志不再 `wait IP_READY`）。
3. `$gnp,*55` 确认参数没被改回。
4. 观察日志出现 `I/user.ntrip recv:`，GGA 质量从 `0/1` 变 `4/5`。
5. 若 4G 一直无 IP，先查 SIM 卡、APN（`$sap,apn,user,pass,*sum`）和 4G 天线。

## 8. 风险提示

- 不要动 GGA/RMC 的输出频率（见 `AIR700E_WATCHDOG_AND_RATE_TRAP.md`）。
- `$snp` 是**全量参数**命令，不是“只改密码”；必须把原有 host/port/mount 一起带上，否则会把其它字段覆盖成空。
- 写入 `$snp` / `$sne` 后模块会重启并重新枚举，串口名会变，操作前先确认当前数据口。
- 改之前先把当前参数读出来（`$gnp`），留好回滚值。

## 9. 2026-11-12 更新：物联网卡更换 + 新账号写入模块

### 9.1 背景：模块断网的真正原因

之前模块侧 NTRIP 一直停在 `wait IP_READY`，根因不是配置，是**模块里那张物联网卡过期了**。

**已更换新的电话卡**，模块侧联网恢复（现场确认）。所以现在模块自己的 NTRIP 客户端可以正常工作了，不再必须依赖主机侧旁路。

> 换了 SIM 之后如果模块仍不上网，先断电重启模块让它重新驻网；APN 用 `$sap,apn,user,pass,*XX` 写入。

### 9.2 新账号（2026-11-18 到期）

| 字段 | 值 |
|---|---|
| host | `120.253.239.161` |
| port | `8002`（WGS84） |
| mount | `RTCM33_GRCEJ`（五星十六频） |
| user | `cvha2771` |
| password | 不记录在本仓库；主机侧在 `~/.config/nodeflow/ntrip_password`(600)，模块侧已写入 NVM |

注意端口映射与旧供应商不同：**新供应商 `8001=CGCS2000`、`8002=WGS84`**，别照旧表填。

### 9.3 写入与回读

写入（密码占位）：

```
$snp,120.253.239.161,8002,RTCM33_GRCEJ,cvha2771,<PASSWORD>,1,*XX
→ $snp,ok,*69
```

回读 `$gnp,*55` 确认（密码打码）：

```
$gnp,120.253.239.161,8002,RTCM33_GRCEJ,cvha2771,<PASSWORD>,1,*1C
```

**回滚值**（换之前的配置，留档）：

```
$gnp,103.40.12.16,8002,RTCM33_GRCEJ,cqcc139580,31818,1,*5B
```

打开 NTRIP 开关：`$sne,1,*49` → `$sne,ok,*7C`。
（同一条命令会同时被 UM982 收到并回 `PARSING FAILED NO MATCHING FUNC SNE`，属正常：`sne` 是 Air700E 应用层命令，不是接收机命令。）

### 9.4 这个 CORS 的握手特性（主机侧旁路踩到的坑）

新 caster 在**收到 GGA 之前不返回任何应答头**。主机侧 `ntrip_client.connect()` 原来是「发请求 → 等 `ICY 200 OK` → 才上行 GGA」，于是与 caster 互相等待直到超时，永远连不上。

已修：`connect(initial_gga=...)` 先上行一次 GGA 再等应答；`run.py` 在没有新鲜 GGA 时不去连。

实测（主机侧，2026-11-12）：

```
→ GET /RTCM33_GRCEJ HTTP/1.0 (Basic auth) + $GPGGA,...
← ICY 200 OK
← RTCM 二进制流
```

### 9.5 结论：已出固定解（2026-11-12 现场确认）

写入并 `$sne,1` 后观察约 90 秒，接收机 GGA 质量仍为 `1`（单点）——根因**不是配置**，而是 SIM 卡选错了运营商：

| SIM | 结果 |
|---|---|
| 联通卡（换卡后误装） | 模块不驻网，NTRIP 停在 `wait IP_READY`，接收机一直质量 `1` |
| **移动卡** | 模块正常驻网，NTRIP 连上 caster，质量直接跳到 `4` |

**这颗模块必须用移动卡。** 换回移动卡并给模块断电重启后，实测 30 秒：

```
GGA 共 22 条，质量分布 {'4': 22}      ← 全部 RTK 固定解
卫星 31、HDOP 0.5
$GNTHS,83.4565,A                     ← 双天线航向有效（A=有效）
$KSXT,20261112085522.90,120.04698655,28.92023045,100.8211,83.45,...
```

定位点约 `28.9202°N, 120.0470°E`，与当时场地一致；航向、俯仰、速度字段均正常输出。

换卡后**没有重新发送 `$sne` 也能工作**，说明 `$snp` 写入的配置重启后直接生效。

### 9.6 主机侧旁路已关闭（2026-11-12）

模块侧联网恢复后，主机侧旁路没有再存在的必要，且两条 VRS 差分同时灌进接收机会互相干扰。已把
`configs/graphs/planning_with_real_rtk.yaml` 与 `examples/` 副本的 `ntrip_enable` 改为 `false`。
需要临时兜底（模块 4G 掉了）时改回 `true` 即可，密码仍在 `~/.config/nodeflow/ntrip_password`。

### 9.7 持久化与断电验证

- `$snp` 按本文档第 4 节记录会写入模块 NVM（上次实测：写完模块自行重启，参数仍在）。
- **未发送 `SAVECONFIG`**：该命令属于 UM982 接收机（保存接收机输出配置），不负责 Air700E 应用里的 NTRIP 参数。
- 异常点：本次写入后模块**没有**触发重启重枚举（端口一直是 `ttyACM3`），与第 4 节记录不同。
- **验证结果：已固化。** 模块断电重启后 `$gnp` 回读仍为新参数：

  ```
  $gnp,120.253.239.161,8002,RTCM33_GRCEJ,cvha2771,<PASSWORD>,1,*1C
  ```

  即 `$snp` 写入确实落到了 NVM，无需额外保存命令。
